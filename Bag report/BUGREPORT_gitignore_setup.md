# Bug Report: .gitignore 設定に伴う不具合と対応

- 対象ブランチ: `Number-guessing-game`
- 発生日: 2026-07-17
- 報告者対応: Claude Code

---

## 1. 何がいけなかったのか（原因）

今回発生していた問題は、独立した4つの不具合が重なったものでした。

### 1-1. `.gitignore` がファイルではなくフォルダになっていた

リポジトリ直下に `.gitignore` という名前の**フォルダ**が存在し、その中に本来配置すべき `.gitignore` **ファイル**が入り込んでいました（`.gitignore/.gitignore`）。

Git は `.gitignore` を「リポジトリ直下にあるファイル」としてしか認識しません。フォルダになっていたためルールが一切適用されず、`Library/` や `Temp/` などの Unity 自動生成物がすべて追跡対象のままになっていました。

### 1-2. .gitignore のテキストが C# スクリプトとして紛れ込んでいた（コンパイルエラーの直接原因）

`Assets/_gitignore.cs` というファイルが存在し、中身は Unity 公式の `.gitignore` テンプレートのテキストそのものでした。

Unity は `Assets/` 配下にある `.cs` ファイルを、中身を問わず自動的に C# スクリプトとしてコンパイルします。中身は `#` から始まる gitignore のコメントや glob パターン（`/[Ll]ibrary/` など）であり、有効な C# 構文ではないため、大量の構文エラーが発生していました。これが「コンパイルエラーが出ている」の直接の原因でした。

### 1-3. プロジェクト内にネストされた git リポジトリが2つ存在していた

`ABC/` と `SAT - program/` の中に、それぞれ独立した `.git` フォルダが存在していました。

**Git の仕様として、あるリポジトリの中に別の `.git` フォルダを置くと、親リポジトリはそのフォルダを通常のディレクトリとしてではなく「埋め込みリポジトリ（gitlink、モード `160000`）」として扱います。** これは正式な Submodule 機能の一部であり、`.gitmodules` で明示的に登録されていれば正しく動作しますが、今回はそれがなく、いわば「野良の埋め込みリポジトリ」でした。

中身が `.gitattributes` / `.gitignore` / `README.md` のみだったことから、GitHub で新規リポジトリを作成した際に生成される雛形を、誤ってこのプロジェクトの中に展開・初期化してしまったものと推測されます。

この壊れた gitlink 参照が原因で `git add .` が

```
error: 'ABC/' does not have a commit checked out
error: unable to index file 'ABC/'
fatal: adding files failed
```

というエラーで失敗していました。

### 1-4. プロジェクトのほぼ全ファイル（386件）がステージ済み削除の宙ぶらりん状態になっていた

`.gitignore` を有効化する過程で、既に追跡済みのファイルをルールに従わせようと `git rm -r --cached` 相当の操作を実行した後、対象を絞らずに **リポジトリ全体** に対して行ってしまったと見られます。結果として `Assets/`・`ProjectSettings/`・`Packages/` などの必須ファイルまで含めて、インデックス上は「削除」、ワーキングツリー上は「未追跡」という不整合な状態になっていました。

※ 実データはディスク上に残っており、データそのものは失われていませんでした。ただしこの状態のままコミットすると、これら全ファイルがリポジトリの履歴上「削除」として記録されてしまう危険な状態でした。

---

## 2. 何を改善したのか（対応内容）

| # | 対応 | 内容 |
|---|------|------|
| 1 | `.gitignore` の配置修正 | `.gitignore/.gitignore` の中身を確認し、標準の Unity 用テンプレートと同一であることを確認した上で、フォルダを解消してリポジトリ直下に正しい**ファイル**として再配置 |
| 2 | コンパイルエラー原因の除去 | `Assets/_gitignore.cs` と対応する `.meta` ファイルを削除 |
| 3 | ネスト git リポジトリの解消（`ABC/`） | `ABC/.git` のみを削除し、中の `.gitattributes` / `.gitignore` / `README.md` を通常ファイルとして親リポジトリに統合（ユーザー承認済み） |
| 4 | ネスト git リポジトリの解消（`SAT - program/`） | 同様に `SAT - program/.git` を削除し、中身を通常ファイル化（ユーザー承認済み） |
| 5 | インデックスの再構築 | `.gitignore` 配置後に `git add .` を実行。`Library/` `Temp/` `Logs/` `UserSettings/` などは正しく除外され、`Assets/` `ProjectSettings/` などの本体ファイルは差分なしとして再追跡された |

最終的にステージされた差分は次の8ファイルのみに収束しました（386件 → 8件）。

- `.vscode/settings.json`（変更）
- `ABC/.gitattributes`, `ABC/.gitignore`, `ABC/README.md`（新規、ネスト解消による通常ファイル化）
- `Assets/_gitignore.cs`, `Assets/_gitignore.cs.meta`（削除）
- `SAT - program/.gitattributes`, `SAT - program/.gitignore`（新規、同上）

## 3. これにおける注意点

- **`.gitignore` は「これから追跡するファイル」にしか効かない。** 既に `git add` 済みのファイルに後から `.gitignore` を適用したい場合は `git rm -r --cached <対象パス>` で明示的にインデックスから外す必要があります。今回のように対象を絞らず `.`（リポジトリ全体）に対して行うと、必要なファイルまで巻き込む危険があるため、必ず対象パスを絞って実行してください（例: `git rm -r --cached Library Temp Logs`）。
- **Git はネストした `.git` を自動的に「埋め込みリポジトリ（gitlink）」として扱う。** 意図せず `git init` 済みのフォルダ（GitHub のテンプレート展開や `git clone` の置き場所を間違えた場合など）をプロジェクト内に置かないよう注意してください。正式にサブプロジェクトとして管理したい場合は `git submodule add` を使うのが正しい方法です。
- **Unity は `Assets/` 配下の `.cs` ファイルを中身に関わらずコンパイル対象にする。** テキストやテンプレートを `Assets/` 内に置く場合は `.cs` 拡張子を避け、`.txt` などにするか、そもそも `Assets/` の外に置くようにしてください。
- **大きな差分件数は異常のサインになりうる。** `git add` の前後で `git status --porcelain | wc -l` のように差分件数を確認する習慣をつけると、今回のような意図しない大量削除に早期に気づけます。
- 今回削除した `ABC/.git` と `SAT - program/.git` の**コミット履歴は失われています**。もしこれらのネストリポジトリに残しておきたい履歴があった場合は復元できないため、今後同様の状況に気づいた際はまず履歴の要否を確認してから対応することを推奨します（今回は中身がテンプレートのみで履歴的価値がないと判断し削除しました）。
